Problem addressed
The prior staff workspace placed a full application overview, evidence list, SAP capture form and event history alongside a long review form. The current state and save/handoff work required too much scanning. This matters to A3 App Usability and App Design as well as a concise live demonstration.

Implemented changes
1. Compact case summary keeps traveller, email, reason, route, flight, booking/channel and synthetic-data boundary immediately visible. Original submission time, ticket value and details remain in a native Application details disclosure.
2. A saved-routing summary shows the authoritative route, queue/owner, reasons and local-rules limitation above the review work. Unsaved checkbox/note changes never masquerade as a saved route.
3. Review work is grouped into Evidence checks, Review route and Review note. Existing control names, IDs, required payment-reference/note rules and event contracts are preserved.
4. A single sticky local action rail groups current saved/unsaved/conflict state, Save local review and the independent queue handoff. Submit buttons explicitly target the review form; handoff stays a separate type=button action using the saved note/current version. Queued cases expose reopening instead of a second handoff.
5. Saved checklist, SAP reference/capture and event history use keyboard-operable native details/summary. SAP errors and pending captures reveal the financial panel automatically. User open/closed choices survive a same-case refresh, reset on a different case owner, and do not cause any write.
6. The generic SAP sample limitation is visible even when the financial panel is collapsed. Captured fields/source/time, raw codes, booking/payment unknowns and every existing recovery control remain available when opened. SAP capture still does not tick evidence checks, establish eligibility or pay a refund.
7. Responsive rules preserve the approved service palette/typeface. On small screens the active review comes before optional saved context; controls use readable mobile type and adequate tap height. The sticky rail is offset above bottom navigation. Reduced-motion and keyboard summary-focus states are included.
