AirAssist V1.2 — 顾问方案执行与复查结论
日期：2026-10-08。范围：A3 应用及支撑证据，本阶段不制作 PPT。

业务结果
这一版完成的是“退款案件准备与交接”的功能原型：旅客提交本地申请 → 显示必要审核缺项 → 人工记录检查和引用证据 → 解释标准/专家分流与责任角色 → 保存后交接 → 必要时带理由重开 → 旅客查询与收据同步当前记录。
它对应 A2 中减少不完整案件、明确标准/异常处理和提高可见性的提案。实际航空公司记录核验、退款资格决定、审批与到账仍需要正式航空和支付接口，不能把准备闭环描述为整个退款业务已上线。

按方案完成的修改
1. 查询绑定提交时的输入和所属视图，取消旧查询，并隔离迟到的成功/失败响应；输入变化时清理旧结果和旧错误。
2. 审核草稿按申请、规范化邮箱和版本保留在当前浏览器会话，刷新不自动写数据库。新版本冲突要求先核对再保留/丢弃，不能静默覆盖。
3. SAP 只读财务参考进入案件上下文：服务器实际 GET，保存白名单返回字段、真实来源、时间、引用备注、捕获版本及本地事件；历史快照不覆盖。
4. SAP 文档不自动核验付款、不勾选审核项、不匹配合成机票、不判断退款资格。通用 USD 净额与合成 NZD 票价保持分离。
5. 修复真实流程验收发现的交接死锁，交接使用最新已保存审核的备注和版本。有未保存内容仍须先处理。
6. 独立复查后修复跨案件财务输入残留及上游布尔金额被当成数字的问题；异常响应保持明确失败，不生成替代快照。
7. 保留已认可的视觉设计，强化草稿/冲突提示，手机次要查询按钮触控高度由38px增至44px。

实际验证
后端：49 项 unittest 全部通过，22.327 秒；含隔离本机数据库、版本并发、资料不足、状态/收据一致性、财务历史、失败不写入等。
前端：23 项实际源码 VM 回归检查全部通过；涵盖异步乱序、取消、草稿与所属案件、冲突、晚到写入、保存后交接等。
浏览器：真实走过新合成案件、标准交接、带理由重开和专家交接。最终案件 AF-21B3A992AD5C 版本7、8个事件，队列 Specialist review，角色 Refund specialist。
SAP：使用本机个人 API Hub key 只读获取公开 sandbox 文档60000002。保存时版本1、2个事件、3项人工检查仍false，handoff仍未准备好。未知文档9999999999显示明确失败，版本和事件数不变。
草稿与并发：实际刷新恢复未存备注；第二窗口保存版本2后，第一窗口旧版本1保存被阻止，并保留原草稿供显式复核。
旅客可见性：错误邮箱只显示未匹配，修改输入后旧错误消失；正确邮箱恢复当前申请。实际下载5042字节JSON收据，其完整record与当前API收据一致，参考快照与案件/进度一致。
手机：390×844测试窗口，实际内容宽375px，scrollWidth375px，无横向溢出；关键按钮46/48px，次要快捷查询44px。键盘申请编号→邮箱→Find case顺序已实际检查。
交付包：当前版本的归档完整性、源文件哈希、实际个人密钥缺失检查及重新解压启动结果，见同目录 PACKAGE_CHECK_V1_2.json 和 PACKAGE_SMOKE_V1_2.json；这些外部报告对应最终归档，不使用自引用包内哈希。
